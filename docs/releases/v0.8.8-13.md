# Pi Agent Desktop 定制版 0.8.8-13

**Windows 启动失败修复版**（macOS / Linux 无功能性变化，但建议一并升级以保持一致）。

## 修复：Windows 客户端启动即报「启动失败」（同事实锤，0.8.8-11 必现）

**现象**：打开应用后窗口与托盘图标正常，内容区显示
「启动失败 — 本地服务没有正常启动」，错误文本 `Next server exited before ready: code=2147483651`。
重装、换安装目录、清用户数据均无效。

**根因**：主进程拉起内置服务时固定传 `--stack-size=16384`（16MB，原意是"深树序列化不爆栈"）。
Windows/Linux 主线程栈保留只有 **8MB**（PE 头 `SizeOfStackReserve` = 8MB）→ V8 在**初始化阶段**
就按 16MB 计算栈边界、直接越界终止：子进程**静默退出、不输出任何 stderr**，
退出码 `0x80000003`（STATUS_BREAKPOINT = 十进制 2147483651），主进程 36ms 后收到退出事件 →
判定"内置服务没起来"。**macOS 分支走 `utilityProcess.fork`，栈由 Electron 准备，因此作者未能复现。**

**修复**：
- 新增 `electron/server-stack.ts`：栈大小收敛为 **10240（10MB）**，全平台统一
  （仍是 V8 默认 ~984KB 的 10 倍，深树序列化足够；实测 Windows 上 8192/10240/12288 正常、16384 必崩）。
- `electron/main.ts` 改为引用该常量（dev spawn / macOS utilityProcess / Windows-Linux spawn 三处同源）。
- **回归门禁**：`electron/server-stack.test.ts` 断言不超过安全上界 12288、且明确禁止 16384。

**为什么之前 CI 没抓到（已补强）**：打包后的冒烟测试 `scripts/smoke-standalone-server.mjs`
起服务时**没带 `--stack-size`** → 走的不是真实 argv。现在它**从 `electron/server-stack.ts` 读同一常量**，
用与主进程完全一致的 argv 起服务，并以 HTTP 200 判定就绪 —— 以后这类"只在真机 argv 上暴露"的问题
会在 Windows CI 直接失败。

## 同事提供的复现（可自行验证）

```powershell
cd "$env:LOCALAPPDATA\Programs\Pi Agent Desktop"
$env:ELECTRON_RUN_AS_NODE=1
# 旧版（1616384，必崩）：无输出、立即退出
.\"Pi Agent Desktop.exe" --stack-size=16384 ".\resources\standalone\server.js"
# 本版（10240，正常）：等待片刻后应看到 Ready / 可访问 http://127.0.0.1:30141
.\"Pi Agent Desktop.exe" --stack-size=10240 ".\resources\standalone\server.js"
```

> 已经手工打过 `--stack-size=10240` 热补丁的机器：**直接安装本版即可**（安装包会覆盖 `app.asar`，
> 热补丁自动失效、无需回退）。

## 其它说明

- **安装包仍未做代码签名**（本仓库发布的是自用构建，未购买代码签名证书）→ 企业终端若拦截，
